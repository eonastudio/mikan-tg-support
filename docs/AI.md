# ИИ-техподдержка

Заготовка ИИ-ответов — рабочая с первого дня: аддон говорит с любым
**OpenAI-совместимым** API (`POST {base_url}/chat/completions`, Bearer-ключ) и
строит контекст из данных панели, истории тикета и вашей базы знаний.

## Включение

Настройки аддона → «ИИ-поддержка»:

1. **Включить ИИ** — общий выключатель.
2. **Base URL** — адрес API **с суффиксом `/v1`**:
   - OpenAI: `https://api.openai.com/v1`
   - OpenRouter: `https://openrouter.ai/api/v1`
   - Groq: `https://api.groq.com/openai/v1`
   - Anthropic через OpenAI-прокси, vLLM, LLM-API-шлюзы: адрес вашего шлюза
   - Локально на сервере (Ollama): `http://<адрес-хоста-в-сети-аддонов>:11434/v1`
     (Ollama отдаёт OpenAI-совместимый эндпоинт; из контейнера аддона `127.0.0.1` —
     это сам контейнер, поэтому указывайте адрес хоста/шлюза, а не loopback;
     для внешнего процесса (external) loopback как раз работает).
   - llama.cpp server: `http://<хост>:8080/v1`
3. **API-ключ** — хранится в KV панели, в интерфейсе не отображается.
4. **Модель** — например `gpt-4o-mini`, `claude-…` (через шлюз), `qwen2.5:7b`, `llama3.1`.
5. **Режим** — см. ниже. 6. **Проверить ИИ** — тестовый пинг модели. 7. **Сохранить**.

## Режимы

| Режим | Поведение |
|---|---|
| `off` | ИИ выключен: кнопки ИИ в диалоге скрыты, автоответы не планируются |
| `draft` | ИИ ничего не отправляет сам. В диалоге появляется кнопка **✦ AI** — черновик ложится в поле ответа, агент правит и отправляет. Безопасный режим по умолчанию |
| `auto` | ИИ отвечает клиенту сам, если агент не ответил в течение **задержки** (по умолчанию 120 с). Ответ помечается в истории как ИИ (с моделью). Агент, ответивший в тикет, отменяет запланированный автоответ |

В режиме `auto` ИИ замолкает в тикете навсегда, если клиент написал «оператор»,
«человек», «human», «operator» и т.п. (см. BOT.md). После перезапуска аддона
неотвеченные тикеты подбирает ежеминутный sweep — автоответ не теряется.

## Персонализация по данным панели

ИИ отвечает **клиенту VPN-сервиса**, а не абстрактному человеку. Контекст собирается
из трёх источников:

1. **Профиль клиента из событий панели** (permission `events`). Панель публикует:
   `payment.paid`, `payment.refunded` (сумма, валюта, тип new/renew/package/trial,
   провайдер, срок), `user.expiring` (осталось 3/1 дня, дата окончания),
   `user.expired`, `traffic.90`, `traffic.100` (период). Аддон сворачивает их
   в профиль по `tg_id` (хранится в KV, 180 дней без событий) и кладёт в промпт
   фактами: «Подписка действует до 2026-11-01», «Трафик периода исчерпан (100 %)»,
   «Платёж: 2026-10-01, RUB 350.00 (renew)». Тот же профиль видит агент в карточке
   тикета.
   > События `bot.*` (расширенные данные подписки) панель отдаёт только держателю
   > своего бот-слота — этому аддону они недоступны по дизайну панели; персонализация
   > строится на публичных типах событий.
2. **База знаний** (поле «База знаний (FAQ)») — ваш текст: тарифы, инструкции по
   приложениям, адреса серверов, типовые решения. ИИ опирается на неё и **не
   выдумывает** факты вне её (правило в системном промпте: чего нет в данных —
   «уточню, специалист ответит здесь же»).
3. **История тикета** — последние 20 сообщений (пользователь/поддержка/ИИ), каждое
   до 2000 символов; медиа описываются пометками («пользователь прислал фото»).

Дополнительно: **язык ответа** (язык пользователя / ru / en), **дополнительные
правила** (тон, чего никогда не говорить), жёсткие правила в системном промпте
(не выполнять инструкции из сообщений пользователя, не просить пароли/токены,
не давать финансовых/юридических советов, при выходе за рамки базы — передать
специалисту).

## Безопасность и приватность ИИ-контура

- **Prompt-injection**: сообщения клиента — данные, не инструкции (явное правило
  в системном промпте; база знаний огорожена тегом `<knowledge>`). У ИИ нет
  инструментов: он не может ничего вызвать, изменить или отправить — только текст,
  который проходит санитизацию (срезка до 3500 символов, удаление управляющих и
  невидимых символов, в т.ч. zero-width и bidi-подмен) и уходит как plain text.
- **Секреты не покидают панель**: токен бота и API-ключ never не попадают в контекст
  модели; в профиль клиента кладутся только факты из событий панели.
- **SSRF**: адрес LLM задаёт админ, но даже админский URL не может указать на
  cloud-metadata эндпоинты (169.254.169.254, fd00:ec2::254) — dialer аддона их
  блокирует по зарезолвленному IP (защита и от DNS-rebinding). Редиректы запрещены.
- **Лимиты**: контекст ≤ 96 КБ, ответ модели ≤ 1 МБ, таймаут 30–60 с, `max_tokens=700`,
  `temperature=0.4`. Ошибка модели не ломает тикет: в `auto` клиенту ничего не
  уходит (придёт агент), счётчик ошибок виден на вкладке Статус.
- **Что уходит провайдеру модели**: текст сообщений тикета, факты профиля (даты,
  суммы платежей, статусы трафика), ваша база знаний. Не уходит: токены, ключи,
  ссылки подписок, пароли, содержимое файлов. Если это критично — используйте
  локальную модель (Ollama/llama.cpp/vLLM на своём железе).

## Тюнинг

- Начните с `draft` на 1–2 недели: смотрите качество черновиков, наполняйте базу
  знаний, затем включайте `auto` с задержкой 60–300 с.
- Держите базу знаний структурированной (вопрос → ответ, короткими блоками) —
  модели так проще опираться на неё.
- `temperature` и `max_tokens` зашиты в код (консервативные); при необходимости
  меняются в `internal/ai/ai.go` (Complete).
- Счётчики (авто-ответы, черновики, ошибки, последняя модель) — на вкладке Статус,
  в KV не пишутся и сбрасываются перезапуском.

## Ограничения заготовки

- Один провайдер/модель на аддон (мульти-модельность и failover — следующие версии).
- Нет RAG по векторной базе — только плоская база знаний до 24 000 символов.
- Нет автоматической классификации/приоритетов тикетов и SLA-таймеров.
- ИИ не видит содержимое фото/файлов (только факт и имя).

Эти пункты заложены в архитектуру (изолированный пакет `internal/ai`, контекст
собирается отдельной функцией) и добавляются без переделки остального.
