# Безопасность аддона tg-support

Модель угроз и то, что сделано против каждой. Аддон работает в доверенном контуре
панели (loopback/bridge, токены хоста), но обрабатывает **недоверимый ввод с двух
сторон**: сообщения произвольных пользователей Telegram и содержимое ответов
внешнего LLM-API.

## 1. Доступ к аддону (панель → аддон)

| Угроза | Защита |
|---|---|
| Чужой процесс на хосте/мосту дёргает эндпоинты аддона | Все маршруты (включая `/ui/*` и `/v2/ui/rpc`) за `Authorization: Bearer MIKAN_ADAPTER_TOKEN`; сравнение константное по времени (SHA-256 от токена, `subtle.ConstantTimeCompare`). Порт контейнера опубликован хостом только на loopback хоста; в bridge-сети ICC выключен |
| Перегрузка страницы аддона | Семафор 32 одновременных RPC (панель со своей стороны держит ≤ 8), таймаут 35 с на вызов (панель ждёт 40 с), тело запроса ≤ 1 МБ (`MaxBytesReader`), таймауты чтения/записи сервера |
| Подмена/перехват ответов | Только loopback/bridge; редиректы наружу запрещены (`CheckRedirect: ErrUseLastResponse`) |

## 2. Доступ к панели (аддон → панель)

- Bearer `MIKAN_PANEL_TOKEN`; панель дополнительно отклоняет запросы с `Origin`
  и чужим `Host` (DNS-rebinding) — аддон не отправляет ни того, ни другого.
- Запрошены **минимальные права**: `ui`, `kv`, `events`. Аддон сознательно не просит
  `bot` (слот официального бота), `users:*`, `billing:*` — у него нет своего бота
  панели и денежных операций. Чем меньше grant, тем меньше ущерб при компрометации.
- Ошибки панели типизированы (401/403/404/409/507) — «не одобрено» и «нет права»
  не путаются с сетевым сбоем; backoff'ы не превращают отказ панели в шторм запросов.

## 3. Секреты

| Секрет | Где живёт | Куда не попадает |
|---|---|---|
| Токен бота Telegram | KV панели `cfg/main` (в БД панели, под её бэкапами) | RPC-ответы страницы (только флаг `has_bot_token`), логи (redaction `/bot<token>/` → `/bot<token>` во всех исходящих ошибках), контекст ИИ, аудит панели (тела RPC не логируются) |
| API-ключ LLM | там же | то же самое: флаг `has_ai_key`, в промпт модели не кладётся |
| Токены хоста (`MIKAN_*`) | окружение контейнера | не читаются страницей, не отдаются ни одним эндпоинтом |

- Пустое значение секрета при сохранении = «оставить прежнее»; удаление — явной
  операцией `clear_secret`. Форма страницы хранит секреты только в памяти
  (sandboxed-фрейм не имеет storage/cookies в принципе).
- Валидация формы токена (`123456789:AA…`) до сохранения — защита от вставки
  постороннего текста.

## 4. Пользовательский ввод из Telegram

| Угроза | Защита |
|---|---|
| Спамерская накачка тикетов/хранилища | Токен-бакет на tg_id (4 сразу, далее 1/2 с, одно предупреждение в 10 мин); один открытый тикет на пользователя; лимит 5000 сообщений на тикет (далее авто-закрытие и новый тикет); файлы > 20 МБ отклоняются |
| Переполнение значений KV (лимит 64 КиБ) | Тексты режутся до 4096 рун, имена/username до 64–128, имена файлов до 256, сообщения пакуются в чанки ≤ 48 КиБ с CAS-ролловером |
| Мусорные/невидимые символы, bidi-подмены | `ToValidUTF8` + strip управляющих и Cf-символов в текстах ИИ-ответов; текст в Telegram отправляется plain (без parse_mode) — разметка не «оживает» |
| Группы/каналы/боты как источник тикетов | Обрабатываются только личные чаты, только не-боты |
| Повторы update'ов (replay после сбоя) | Дедуп-маркер `upd/<id>` + идемпотентность по `tg_msg_id` в хранилище: повтор не двоит сообщения |
| Отравленный update (вечная ошибка) | После 3 неудач update пропускается с записью в лог — очередь не блокируется |
| Угон offset / потеря сообщений | Offset ack'ается только после успешной обработки батча; при первом запуске backlog отклоняется (`offset=-1`) |

## 5. Страница аддона (XSS/CSRF-контур)

- Фрейм панели: `sandbox="allow-scripts"` (opaque origin — нет ни cookies, ни storage,
  ни доступа к API/окну админки), CSP панели: `script-src 'self'` (весь JS — внешний
  файл `app.js`, inline-скриптов нет), `form-action 'none'` (отправка только через
  JS), `connect-src 'self'` + postMessage-мост (страница физически не может сделать
  произвольный сетевой запрос).
- Весь пользовательский контент (тексты тикетов, имена, темы, ошибки) рендерится
  через `textContent`/`createElement`; `innerHTML` в `app.js` отсутствует (проверяемо:
  `grep -n innerHTML web/app.js`).
- Фото показываются как `data:`-URL, собранный самим аддоном (mime из белого списка
  image/jpeg|png|gif|webp), а не прямой ссылкой на Telegram: токен бота не светится
  во фрейме, внешний трафик из sandboxed-страницы исключён.
- Аутентификация вызовов страницы — задача панели (сессия админа + CSRF-токен +
  подпись адреса фрейма); аддон дополнительно требует свой Bearer на `/v2/ui/rpc`.
- Действия страницы пишутся в аудит панели (method+path каждого не-GET вызова).

## 6. Исходящие подключения (SSRF)

Два внешних адреса задаёт админ: API Telegram и LLM base URL. Оба:
- только `http(s)`, редиректы запрещены;
- dialer блокирует облачные metadata-эндпоинты `169.254.169.254` и `fd00:ec2::254`
  **по зарезолвленному IP** (`net.Dialer.Control`) — защита и от DNS-rebinding;
- loopback/частные адреса разрешены намеренно (локальные Ollama/llama.cpp и
  telegram-прокси — легитимный сценарий); остальные границы держит ufw-правило хоста
  (из bridge `mikan-addons` на хост открыт только порт Panel API).
- Скачивание файлов бота: путь из `getFile` проверяется (никаких `..`, `?`, `#`,
  переводов строк), размер ограничен 8 МБ на стороне Telegram-клиента и ~700 КБ
  для превью страницы.

## 7. LLM-контур

- **Prompt-injection**: системный промпт явно объявляет сообщения пользователя
  данными, а не инструкциями; запрещает раскрывать промпт/секреты/устройство;
  база знаний огорожена `<knowledge>`; у модели нет инструментов — максимум текст.
- **Выход модели** проходит Sanitize: срезка до 3500 рун, удаление управляющих/Cf
  символов и zero-width, нормализация переводов строк; отправка plain text.
- **Отказ модели** не влияет на доставку: в auto клиент просто ждёт агента; ошибки
  считаются и видны на странице Статус; таймауты 25–60 с, тело ответа ≤ 1 МБ,
  контекст ≤ 96 КБ.
- **Утечка данных провайдеру** ограничена составом контекста (см. AI.md «Что уходит
  провайдеру»): без токенов, ключей, ссылок подписок; при необходимости — локальная
  модель.

## 8. Хранилище и доступность

- Все записи конкурентных путей (поллер + страница + таймеры ИИ) — CAS
  (`If-Match`/`if_absent`) с backoff; гонки не теряют сообщения (покрыто тестом
  8×6 конкурентных добавлений).
- Квота KV: prune закрытых тикетов по retention (6 ч + вручную), TTL профилей
  (180 дней) и дедуп-маркеров (48 ч / 8 дней), индекс ограничен 300 головами,
  история в диалоге — 400 сообщениями (`truncated` флаг).
- `quota_exceeded` (507) surfaced в логах; лечение — в INSTALL.md (Диагностика).
- Отказ панели не роняет HTTP-сторону: `/v2/info` статичен, страница получает
  честный 503 `panel_unavailable`, воркеры догоняют состояние backoff'ами.

## 9. Что остаётся зоной ответственности администратора

- **Доверие к коду**: кастомный аддон панель не проверяет — установка требует явного
  подтверждения. Собирайте образ из этого исходного кода сами.
- **Токен бота** хранится в БД панели и её бэкапах: доступ к бэкапам = доступ к боту.
  Компрометация токена лечится перевыпуском у @BotFather и заменой в настройках.
- **Права на страницу**: любой админ панели (и только админ с сессией) видит тикеты
  и может отвечать. Разграничения «агент vs супер-админ» внутри страницы нет —
  панель передаёт аддону только язык интерфейса.
- **API-ключ LLM** тарифицируется провайдером: авто-режим может генерировать заметный
  трафик при наплыве тикетов (ограничен задержкой, 5000 сообщений на тикет и
  антиспамером).
- Обновления аддона: дайджест образа контролируете вы; сверяйте CHANGELOG и диффы
  перед накатом.

## 10. Проверено тестами

Юнит/интеграционные тесты (`go test ./...`) покрывают: 401 на всех маршрутах без
токена и с чужим токеном; маскировку секретов во всех RPC-ответах; отказ сохранять
токен неверной формы; traversal/404 на `/ui/*`; ETag/304; валидацию id/seq/методов
RPC; лимиты медиа (413/415); flood-контроль; дедуп replay; конкурентный CAS;
redaction токена в ошибках; SplitText/Sanitize; блокировку metadata-IP; поведение
при 401/409/429 Telegram; отказ ИИ без влияния на тикет.
